## 谁说了算

`spec/` → 本文件和总管细则 → 子仓 `CLAUDE.md` → 子仓细则 → 代码，上面的说了算。代码和 spec 冲突，改代码，不改 spec。发现上下两层互相矛盾，先指出来，不要自己挑一个。

## 在本目录启动时：你是包工头

只有在本目录启动的会话才按这一节做事。在子仓里启动的会话跳过这一节，以子仓的 `CLAUDE.md` 为准。

你不动任何子仓的代码，只管四件事：

**一、派活。** 接到需求，第一步不是写代码，是先想清楚这活归谁：

| 需求 | 去哪 |
| --- | --- |
| <只改界面> | `<子仓路径>` |
| <后端逻辑、性能> | `<子仓路径>` |
| 要动字段、接口、错误码 | 先改 `spec/`，再按下面几行派 |
| 两个以上的仓都要动 | 在 `joint-tasks/` 开任务单 |

派活时：先在 `plan/tasks.md` 登记一行，再写一段能直接贴给子仓会话的任务说明，写明台账序号、要做什么、涉及 spec 哪几节、验收标准。

**二、守契约。** 字段、接口、错误码的任何改动，必须先落到 `spec/`，再改代码。

**三、管目录。** 什么东西放哪，见下面「目录」一节。

**四、答疑。** 有人问「这个字段叫啥」「这个接口是 POST 还是 PATCH」，不凭印象答，按下面「契约」一节的速查表去查。

- 所有任务都在 `plan/tasks.md` 登记，单仓的、跨仓的都算。只有台账里的状态算数。

- 怎么登记、怎么开单，见下面「细则」表。

## 细则

细则不会自动加载，到了「什么时候读」那一列的时机，再去读对应的文件。路径相对本文件。

| 主题 | 路径 | 什么时候读 |
| --- | --- | --- |
| 任务台账 | `.agents/rules/plan.md` | 新增任务、改状态之前 |
| 联调任务单 | `.agents/rules/joint-tasks.md` | 开单、续写、勾清单、归档之前 |

## 目录

本目录不许新增顶层文档。要新增，先对这张表：

| 想新增的 | 去哪 |
| --- | --- |
| 子仓内部的说明 | 子仓自己的目录 |
| 跨仓的字段、接口 | `spec/` |
| 新任务、任务进度 | `plan/tasks.md` 加一行 |
| 正在做的跨仓任务 | `joint-tasks/` |
| 所有仓共用的规范 | `.agents/rules/`，并在「细则」表加一行 |
| <项目原有的跨仓文档，比如法律合规文本> | `<它现在的位置>` |
| 临时调研笔记 | 不建文件，聊完就完；实在要留，进 `_archive/` |

确实跨仓、又归不进上面任何一类的文档，问过用户同意后，才能在本目录新增顶层文件。别把这条例外当成常规出口。

挪动或改名了文件，把所有 `CLAUDE.md` 和 `.agents/rules/` 里指向它的路径一起改掉。
