## 谁说了算

`spec/` → 本文件 → 细则 → 代码，上面的说了算。代码和 spec 冲突，改代码，不改 spec。发现上下两层互相矛盾，先指出来，不要自己挑一个。

## 红线

- spec 里没有的字段、接口、错误码，一个都不许引进来。确实需要，先改 spec，再写代码。
- 本地实现和 spec 对不上，停下来对齐，不许边写边改。

## 契约

引用契约只写章节号，比如「见 §6.2」，不复制原文。章节号永远不改、不复用。查东西先去这里：

| 问题 | 第一查 |
| --- | --- |
| 字段叫什么 | `spec/<NN-数据模型>.md` |

## 目录

| 想新增的 | 去哪 |

| 新任务、任务进度 | `plan/tasks.md` 加一行 |
