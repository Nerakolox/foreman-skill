# 任务台账

适用：新增任务、开始干活、做完、废弃、拆分，只要任务状态变了，改 `plan/tasks.md` 之前读这份。

## 规矩

- `plan/tasks.md` 是所有任务的唯一进度记录，单仓的、跨仓的都登记。对话里说「做完了」不算，改了台账才算。
- 状态一变，立刻改台账，不攒着。
- 新任务在表格末尾加一行，序号接着最大的往下编，不复用。
- 废弃的任务不删行，状态改成 `已废弃`，说明里写原因。
- 跨仓任务：台账一行，加一份 `joint-tasks/` 任务单，说明里写任务单文件名。任务单归档时，这一行改成 `已完成`。
- 做出了设计决定的任务：结论写进 `spec/10-decisions.md`，台账只改状态。
- 引用契约只写章节号，不复制原文。

## 谁来改

- 包工头派活时登记，状态 `计划中`。
- 子仓会话开工时改成 `开发中`，做完改成 `待验证` 或 `已完成`。只改自己仓的行。
- 子仓会话接到台账里没有的活，先自己加一行，再动手。

## 字段

| 字段 | 写什么 |
| --- | --- |
| 序号 | 全局递增整数 |
| 任务 | 简短、唯一 |
| 仓 | <子仓> / <子仓> / 总管 / 多仓 |
| 说明 | 一行，必要时引章节号；跨仓任务写任务单文件名 |
| 依赖 | 依赖哪几行的序号，没有写 `—` |
| 状态 | 见下 |

## 状态

| 状态 | 含义 |
| --- | --- |
| `计划中` | 已登记，还没开始 |
| `开发中` | 有人在做，或者有本地改动 |
| `待确认` | 等别人拍板或补信息 |
| `待验证` | 代码写完了，但没在真实场景跑过。**不能当完成用** |
| `已完成` | 验证通过 |
| `已废弃` | 不做了，行保留 |

`待验证` 和 `已完成` 最容易混：能编译不等于验证过。接口没真调通、脚本没在真环境跑过，都是 `待验证`。
